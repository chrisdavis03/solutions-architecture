# Patterns

A pattern here is a reusable solution write-up: the problem it solves, the context where it applies, the solution itself, the tradeoffs you accept, and when *not* to use it. Write it so a future reader can decide whether it fits their situation, not just copy the answer.

For the longer form, start from `templates/design-doc.md` and trim it down. Keep each pattern in its own file, named for the problem (`idempotent-consumers.md`), not for the technology.

Dated blog drafts and one-off war stories belong in `posts/`. If it only made sense on one project, it is a post, not a pattern.
